# 1\.3 高擎GD电机 CAN 通信协议解析手册

版本 1\.0 \| 经典 CAN \| 29\-bit 扩展帧 \| 1 Mbps \| 单帧 ≤ 8 字节

# 协议解析

## CAN ID

本协议基于**经典 CAN**总线，主要技术参数如下：

|**参数**|**说明**|
|---|---|
|总线类型|经典 CAN|
|帧格式|29\-bit 扩展帧（有效位 \[19:0\]，其余位必须为 0）|
|波特率|1 Mbps（仲裁段与数据段同速率，无 BRS）|
|单帧最大长度|8 字节|
|字节序|小端序（低字节在前）|

**表 1 — CAN ID 位布局**

|**Bit**|**\[29:19\]**|**\[18\]**|**\[17:16\]**|**\[15\]**|**\[14:8\]**|**\[7\]**|**\[6:0\]**|
|---|---|---|---|---|---|---|---|
|含义|保留|CAN\_MIT|数据类型|帧方向|发送端ID|一拖多标识|电机端ID|
|取值|均需为0|0=不启用 CAN\_MIT 模式<br>1=启用 CAN\_MIT 模式|00=int16<br>01=int16|1=发送给电机的控制帧<br>0=接收电机状态的返回帧|1\~126|本工程未使用|1\~126|

CAN ID = **标题宏 \| 电机ID**。发送时**发送端 ID 填在末尾的低位** \(`0x...XX`\)，返回时**电机端 ID 与发送端 ID 位置互换**

**注意：**

- 受经典 CAN 8 字节数据区限制，本工程**仅支持 int16 数据类型**（bits\[17:16\]=01）；

- 位布局中的 \[7\] 一拖多标识在本工程中**未使用**，一拖多（一帧控制多台电机）协议已删除，本手册不再介绍；

- 启用 CAN\_MIT 模式（\[18\]=1）时，CAN ID 采用 `0x58000 | 电机ID`，数据区为 MIT 专用打包格式（详细见 [1\.3 高擎GD电机 CAN 通信协议解析手册](https://lingdongfangcheng.feishu.cn/wiki/RKklw9ZYLiQs5Gk14fkccVamnPb?larkTabName=space#share-RcoDdM6NBoOFlYxlqtRcOZUynFf)）；

- 数据类型是用于切换协议中各个参数的占用字节和刻度转换系数，本工程固定为 int16；

例：**CAN ID 构成**（ 不同电机 ID）：

|数据类型|发送标题宏|发送 CAN ID \(ID → bits\[7:0\]\)|返回 CAN ID \(ID → bits\[14:8\]\)|
|---|---|---|---|
|int16|0x18000|`0x18001`|`0x10100`|
|int16|0x18000|`0x18009`|`0x10900`|
|int16|0x18000|`0x18007`|`0x10700`|
|MIT|0x58000|`0x58012`|`0x1``1``2``0``0`|

> **发送**：电机 ID 填在 **bits\[7:0\]**（`0x180xx`，`xx` = 电机 ID，低 8 位）。 **返回**：电机 ID 移到 **bits\[14:8\]**（`0x10xx00`，`xx` = 电机 ID，占第 8\~14 位）。 即发送/返回时电机 ID 在 **bits\[7:0\] ↔ bits\[14:8\] 之间互换位置**（对应 §1\.1 位布局表）。

## 单电机发送帧

每帧 = **模式码 \(1字节\)** \+ **查询码 \(1字节\)** \+ **参数 \(小端序\)**。

通用结构如下各模式的模式码、帧长、参数见 **表 2**（§6）。查询码含义见 §1\.3，数据换算见 **表 4**（§6）：

|**字节**|**Byte0**|**Byte1**|**Bytes\[2\-N\]**|
|---|---|---|---|
|含义|模式码|查询码|参数 \(小端序\)|
|取值|0x01\~0x21|0x0E（状态查询）<br>0x04/0x05/0x07（版本/型号查询）|长度由模式决定（int16）|

### 换算系数 \(物理值 → 原始值\)

各物理量在 int16 数据类型下的换算系数见 [表4\-常用单位说明](https://lingdongfangcheng.feishu.cn/wiki/CKnMwHh4iiCFankuc4aciBCfnNf)。

### 示例一：VEL 速度控制 \(模式码 0x1C, int16\)

ID为1的电机 以 0\.1 圈/s 转动，数据类型 int16，CAN ID=0x18001：

|格式|**CAN ID**|**Byte0 \(模式码\)**|**Byte1 \(查询码\)**|**Bytes\[2\-3\] \(目标速度\)**|
|---|---|---|---|---|
|Hex|0x18001|1C|0E|90 01|
|解析|发送帧：<br>int16，ID为1的电机|模式 ：<br>VEL\(0x1C\)|查询码：<br>0x0E|`90 01` 解析为 0x0190，<br>十进制原始值 400 → 目标速度 0\.1 圈/s|

### 示例二：POS\_VEL\_TQE 位置\+速度\+力矩 \(模式码 0x1F, int16\)

ID为1的电机以 0\.5 圈/s 速度转到 0\.5 圈位置，力矩上限 1\.0 Nm，数据类型 int16，CAN ID=0x18001：

|格式|**CAN ID**|**Byte0 \(模式码\)**|**Byte1 \(查询码\)**|**Bytes\[2\-3\] \(目标位置\)**|**Bytes\[4\-5\] \(最大速度\)**|**Bytes\[6\-7\] \(力矩上限\)**|
|---|---|---|---|---|---|---|
|Hex|0x18001|1F|0E|88 13|D0 07|64 00|
|解析|发送帧：int16，ID为1的电机|模式 ：<br>POS\_VEL\_TQE\(0x1F\)|查询码：<br>0x0E|`88 13` 解析为 0x1388，<br>十进制原始值 5000 → 目标位置 0\.5 圈|`D0 07` 解析为 0x07D0，<br>十进制原始值 2000 → 最大速度 0\.5 圈/s|`64 00` 解析为 0x0064，<br>十进制原始值 100 → 力矩上限 1\.0 Nm|

### 示例三：MIT 运控模式（模式码 0x21）

MIT 的 8 字节里**没有模式码和查询码**，而是把 `pos / vel / tqe / kp / kd` 五个参数按位拼成一个 64 位整数，再按低字节在前切成 8 个字节。因此会出现「一个字节里装了前后两个字段的各半个字节」。

**本例条件**：ID=1 的电机，`pos=0`、`vel=0`、`tqe=0`、`Kp=10`、`Kd=1`，CAN ID=`0x58001`。

#### 第 1 步：物理值 → 原始值

MIT 用的是**偏移码**：物理值 0 不等于 原始值为 0，而是落在量程中点。公式：

```Plain Text
raw = (物理值 − 量程下限) × (最大位宽 − 1) ÷ (量程上限 − 量程下限)
```

#### 第 2 步：把 5 个 原始值 按位排队（64 位）

#### 第 3 步：每 8 位隔断一次，低字节在前 → 8 字节

#### 第 4 步：最终帧

> 整帧 8 字节全部是打包参数，**没有模式码和查询码**；接收方靠 CAN ID 的 \[18\]=1 识别这是 MIT 帧。打包与量程详见 §2\.11。
> 
> 

## 返回帧（通用）

`单电机模式` 返回帧结构：Byte 0 = **查询码**，后续为返回参数，且参数为查询数据 \(小端序\)。返回帧 CAN ID = 0x10000 \+ motor\_id × 256 \(如ID为1的电机  → 0x10100\)。

### 查询码与返回参数

注：发送帧 Byte 1 \(查询码\) 决定电机返回哪些数据，且**返回数据的字节长度由控制帧的数据类型决定**（本工程固定 int16）。

查询码\(query\)会原样回传至返回帧的 Byte0 位：

|**查询码**|**含义**|**返回参数**|**int16 帧长**|
|---|---|---|---|
|0x0E|标准状态（无模式字段）|查询码，错误码，位置，速度，力矩|查询码（1字节）<br>错误码（1字节）<br>位置（2字节）<br>速度（2字节）<br>力矩（2字节）|
|0x04|固件版本|查询码，固件版本|4字节|
|0x05|硬件版本|查询码，硬件版本|4字节|
|0x07|电机型号|查询码，电机型号|2 \+ 型号长度 字节|
|0x03|系统命令应答|查询码，执行结果|2字节|

> 本工程状态查询统一使用 **查询码 0x0E**，返回帧长度恰为 8 字节，适配经典 CAN 数据区。原 FDCAN 协议的 0x0B / 0x0C / 0x0D 查询码因超出 8 字节或未实现，均已删除。
> 
> 

### 示例返回帧：查询码 0x0E

CAN ID=0x10100 \(电机 1\), 数据 = 0E 00 C8 00 90 01 03 00

|格式|**CAN ID**|**Byte0**|**Byte1**|**Bytes\[2\-3\]**|**Bytes\[4\-5\]**|**Bytes\[6\-7\]**|
|---|---|---|---|---|---|---|
|Hex|0x10100|0E|00|C8 00|90 01|03 00|
|解析|ID为1的电机 ，返回帧，int16，<br>\(CAN ID=0x10000\|100\)|查询码：<br>0x0E|错误码：<br>0x00 \(无错误\)|C8 00 解析为 0x00C8，<br>十进制原始值 200 →<br>当前位置 0\.02 圈|90 01 解析为 0x0190，<br>十进制原始值 400 → <br>当前速度 0\.1 圈/s|03 00 解析为 0x0003，<br>十进制原始值 3 → <br>当前力矩 0\.03 Nm|

# 模式详解

- 每帧 = **模式码 \(1字节\)** \+ **查询码 \(1字节\)** \+ **参数 \(小端序\)**。以下表格中查询码统一用**`0X0E`**查询，CAN ID = `标题宏 | 电机ID`（标题宏见下表）。

- 受经典 CAN 8 字节数据区限制，本工程**所有模式仅提供 int16 版本**。

|数据类型|CAN标题宏|
|---|---|
|int16|0x18000|
|MIT|0x58000|

|---|---|---|---|---|

## MIT模式 \(模式码 0x21 \)

- 输出力矩 = \(目标位置 − 实际位置\) × Kp \+ \(目标速度 − 实际速度\) × Kd \+ 前馈力矩。

- 受经典 CAN 8 字节限制，**MIT 模式不再使用「模式码 \+ 查询码 \+ 参数」结构**，而是将 5 个参数压缩进 8 字节数据区，并用 CAN ID 的 \[18\] 位标识 MIT 模式。

**CAN ID** = `0x58000 | ID`（0x58000 已包含 \[18\]=1、\[17:16\]=01、\[15\]=1）。

**数据区打包（8 字节，小端 / 位域拼接）**：

5 个参数首尾相接拼成一个 64 位原始值，低字节在前（小端）写入 8 字节数据区。各字段占用的位区间与字节如下（位序为 1 基，bit 1 = 最低位）：

|**CAN ID**|**bit 1\~16**|**bit 17\~28**|**bit 29\~40**|**bit 41\~52**|**bit 53\~64**|
|---|---|---|---|---|---|
|0x58000 \| ID|pos（16 bit）|vel（12 bit）|tqe（12 bit）|kp（12 bit）|kd（12 bit）|
|占用字节|Byte0、Byte1|Byte2、Byte3 低4位|Byte3 高4位、Byte4<br>|Byte5、Byte6 低4位|Byte6 高4位、Byte7|
|量程（物理值）|−3\.2768 \~ \+3\.2767 圈|−10 \~ \+10 圈/s|−100 \~ \+100 Nm|−800 \~ \+800|−200 \~ \+200|

> **Byte3、Byte6 是「拼接字节」**：低 4 位属于前一个字段，高 4 位属于后一个字段（例如 Byte3 = vel 高 4 位 \+ tqe 低 4 位）。解析时先按 CAN ID 的 \[18\]=1 判定为 MIT 帧，再按上表取位。
> 
> 

**各字段位域分配**：

|**字段**|**位宽**|**位区间**|**占用字节**|**量程（物理值）**|**说明**|
|---|---|---|---|---|---|
|pos|16 bit|bit\[15:0\]|Byte0（低8位）、Byte1（高8位）|−3\.2768 \~ \+3\.2767 圈|目标位置|
|vel|12 bit|bit\[27:16\]|Byte2（低8位）、Byte3 低4位|−10 \~ \+10 圈/s|目标速度|
|tqe|12 bit|bit\[39:28\]|Byte3 高4位、Byte4|−100 \~ \+100 Nm|前馈力矩|
|kp|12 bit|bit\[51:40\]<br>|Byte5（低8位）、Byte6 低4位|−800 \~ \+800|控制增益|
|kd|12 bit|bit\[63:52\]|Byte6 高4位、Byte7|−200 \~ \+200|控制增益|

> **注意 Byte3 与 Byte6 是「拼接字节」：一个字节里塞了两个字段各半个字节——低 4 位属于前一个字段，高 4 位属于后一个字段**。
>

# 版本查询

统一使用 `int16 (CAN ID=0x18000 | ID)`，发送查询码，电机返回相应数据。

### 固件版本 \(查询码 0x04\)

发送帧：

|**CAN ID**|**Byte0**|**Byte1\(查询码\)**|
|---|---|---|
|0x18000 \| ID|0x00|0x04|

返回帧：

|**CAN ID**|**Byte0\(查询码\)**|**Byte1**|**Byte2**|**Byte3**|
|---|---|---|---|---|
|0x10000 \| （ID\<\<8）|0x04|patch|minor|major|

> 版本号 = **major\.minor\.patch**，三个字段各占 1 字节直接存放（不是位打包）。
> 
> 

**示例**：返回 `04 08 01 00` → patch=0x08, minor=0x01, major=0x00 → 固件版本 **0\.1\.8**。

查询电机 2 发送 `0x18002`，返回 `0x10002`，依此类推。

### 硬件版本 \(查询码 0x05\)

**发送帧：**

|**CAN ID**|**Byte0**|**Byte1\(查询码\)**|
|---|---|---|
|0x18000 \| ID|0x00|0x05|

**返回帧：**

|**CAN ID**|**Byte0\(查询码\)**|**Byte1**|**Byte2**|**Byte3**|
|---|---|---|---|---|
|0x10000 \| （ID\<\<8）|0x05|patch|minor|major|

> 与固件版本结构相同，仅 Byte0 标识不同（0x05）。
> 
> 

### 电机型号 \(查询码 0x07\)

**发送帧：**

|**CAN ID**|**Byte0**|**Byte1\(查询码\)**|
|---|---|---|
|0x18000 \| ID|0x00|07|

**返回帧：**

|**CAN ID**|**Byte0\(查询码\)**|**Byte1**|**Bytes\[2\-1\+model\_len\]**|
|---|---|---|---|
|0x10000 \| （ID\<\<8）|0x07|model\_len|型号数据 \(ASCII 字符\)|

> 型号数据为 **ASCII 字符直读**，`model_len` 个字符直接拼成型号字符串（如 `0x35`=`'5'`、`0x5F`=`'_'`）。
> 
> 

**示例**：发送 `00 07`，返回 `07 07 35 30 33 36 5F 30 32` → model\_len=7，型号 = **5036\_02**。返回帧数据长度 = 2 \+ model\_len。
